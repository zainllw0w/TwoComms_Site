# Non-DTF CSRF-exempt endpoint contracts

Status: Stage 4 DJ6-SEC-003 inventory and test contract. This document does
not remove or change any exemption. It records the compensating control that
must replace Django CSRF for each executable exemption site and the negative
tests required before a future change is released.

The static inventory has 25 executable occurrences: 20 function decorators
(including the internal Monobank signature helper) and 5 URL-level wrappers.
The Django 6.1 plan's historical grep count of 26 includes the explanatory
`@csrf_exempt` text in `twocomms/storefront/urls.py:157`; comments are not
endpoints and are intentionally excluded by the no-network validator.

`twocomms/storefront/views.py.backup` is executed by the active
`SourceFileLoader` path behind `_legacy_view`. All seven backup decorators are
therefore inventoried below. Four names are loaded by `_LEGACY_VIEW_NAMES`, but
their outer `_legacy_view` closures are not CSRF-exempt, so the inner decorator
does not reach `CsrfViewMiddleware`; three decorated names are not loaded and
their routes use modular handlers. The machine-check fails if this loader map,
route wrapper status, or documentation drifts.

`_LEGACY_VIEW_NAMES` set, all seven backup decorators, and the `_legacy_view`
route wrappers. It intentionally does not modify the legacy file or remove any
decorator.

## Required gate

Run the no-network validator from the repository root:

```bash
TWC_PYTHON="$(cd "$(git rev-parse --git-common-dir)/.." && pwd)/.venv/bin/python"
test -x "$TWC_PYTHON"
"$TWC_PYTHON" scripts/check_csrf_exempt_contract.py
"$TWC_PYTHON" -m unittest tests/test_csrf_exempt_contract.py
```

The validator parses only local Python AST and this Markdown table. It fails on
any active exemption without a row, any row without an active source site, or
missing contract columns. It does not import Django, open sockets, call a
provider, mutate a database, or remove a CSRF exemption.
